# entity-state-replication-go

多人在线场景下的实体状态同步能力。服务端维护共享世界的权威状态，客户端持续看到自己附近实体的最新变化。网络通道会丢包、乱序、重复且带宽有限，本机制在实体数量增长后仍保持可用的带宽占用与延迟。

## 架构

```
client                          server
  |                               |
  |--- JoinRequest -------------->|  会话建立
  |<-- JoinAck -------------------|
  |<-- Snapshot(full baseline) --|  完整基线（可重传）
  |--- Ack --------------------->|
  |                               |
  |--- Input(seq) -------------->|  输入校验 + 确定性应用
  |<-- Snapshot(delta) ----------|  增量快照（绝对值）
  |--- Ack --------------------->|
  |            ...                |
```

通道（`transport.Channel`）是 tick 驱动的不可靠传输，模拟丢包、乱序、重复、延迟与有限带宽。服务端与客户端按固定 tick 步进。

## 同步语义

### 1. 服务端权威

- 客户端提交的输入**不直接改变**共享状态。输入经过校验后按确定顺序应用：同一 tick 内按 `(clientID, inputSeq)` 排序。
- 重复输入（seq 已处理）与过期输入（seq 小于已处理最大值）被忽略，不产生任何效果。
- 输入校验包括：会话存在性、实体归属、seq 单调性、移动向量长度钳制。

### 2. 增量同步（绝对值快照）

快照携带的是字段的**绝对值**而非相对增量：

```go
type Snapshot struct {
    Tick        uint64
    BaseTick    uint64   // 增量基于哪个已确认 tick
    AckInputSeq uint64   // 服务端已处理的最高输入 seq
    Full        bool     // 基线标记
    Entities    []EntitySnapshot  // 进入或更新的实体（仅变化字段）
    Leaves      []EntityID       // 离开视野的实体
}
```

- 增量 = 当前可见集 与 基线（客户端已知状态）的 diff：
  - 新进入视野的实体 → 全字段快照（`AllFields`）
  - 已有实体 → 仅变化字段的快照
  - 离开视野的实体 → leave 列表
- 因为是绝对值，客户端**跳过错乱或丢失的快照**后应用更新的快照仍然正确，不会累积误差或回退。
- 实体频繁增删时，增量重建结果与全量一致（有测试覆盖）。

### 3. 丢包 / 乱序 / 重复

- 客户端**严格按 tick 升序**应用已缓冲的快照，跳过缺失的 tick（丢包），丢弃过期快照（`tick <= lastApplied`）。
- 重复快照（相同 tick）只应用一次。
- 短暂丢包后，服务端下一个增量快照基于客户端最后确认的 tick，包含该 tick 之后的所有变化，客户端应用后即收敛到最新权威状态。

### 4. 视野范围（AOI）

- 服务端按每个客户端的视野中心（其控制的实体位置）与半径筛选可见实体。
- 实体进入视野 → 全字段快照；离开 → leave 事件。单个实体的进出不影响其他实体的同步。
- 客户端对进入的实体做**淡入**、离开的实体做**淡出**后清理，过渡平滑。

### 5. 带宽与频率退让

- 服务端对每个客户端有快照字节预算（`SnapshotBudget`）。超出预算时：
  - 客户端**自己的实体**优先保证；
  - 其余实体按离视野中心的距离排序，并带**轮转偏移**（持续拥塞时每个实体都有机会被更新）；
  - 被截断的实体保留在脏集合中，下一个快照继续发送，不丢失。
- 客户端只确认**完整**快照；部分快照不推进基线（`ackedTick`），保证被延迟的实体不会因基线前移而丢失。
- 旧快照可被丢弃（跳过 tick），但可见状态永不回退。

### 6. 客户端预测与平滑修正

- 客户端对自己控制的实体做**本地预测**：输入立即生效，不等服务端往返。
- 收到权威快照后，按 `AckInputSeq` 回退到权威位置，重放之后的所有输入，得到修正后的模拟位置。
- 渲染位置以 `CorrectionRate` 平滑追赶模拟位置，**不产生可见跳变**。
- 预测只影响自己的实体；其他实体通过独立的插值历史渲染，互不干扰。

### 7. 中途加入

- 握手：客户端发送 `JoinRequest`，服务端创建/复用会话并回 `JoinAck`（分配实体）。
- 基线：服务端在客户端确认前**每 tick 重发全量基线**，直到收到确认。
- 客户端在收到完整基线前 `Render` 返回 nil，**不呈现半初始化状态**。
- 握手或基线超时（`JoinTimeout`）时，客户端**清空所有缓冲状态**后重新握手，不残留脏状态。
- 同一客户端重复加入时，服务端复用其实体、重置会话基线。

## 可配置项

### `world.Config`
| 字段 | 默认值 | 说明 |
|------|--------|------|
| TickRate | 20 | 服务端每秒 tick 数 |
| MoveSpeed | 5 | 移动速度（单位/秒） |
| HistoryLen | 256 | 保留的历史 tick 数（增量基线用） |

### `transport.Config`
| 字段 | 默认值 | 说明 |
|------|--------|------|
| Loss | 0.05 | 丢包概率 [0,1] |
| Duplicate | 0.05 | 重复概率 [0,1] |
| Reorder | 0.1 | 乱序概率 [0,1] |
| Latency | 2 | 基础延迟（tick） |
| Jitter | 2 | 随机抖动（tick） |
| Bandwidth | 0 | 每 tick 投递字节数；0 = 不限 |
| MaxInFlight | 256 | 在途消息上限（拥塞丢包） |
| Seed | 1 | 随机种子（可复现） |

### `server.Config`
| 字段 | 默认值 | 说明 |
|------|--------|------|
| ViewRadius | 30 | 视野半径 |
| SnapshotBudget | 0 | 每客户端每 tick 快照字节预算；0 = 不限 |
| SendEvery | 1 | 每 N 个 tick 发送一次快照 |

### `client.Config`
| 字段 | 默认值 | 说明 |
|------|--------|------|
| TickRate | 20 | 客户端每秒步数（需与服务端一致） |
| MoveSpeed | 5 | 预测速度（需与服务端一致） |
| InterpDelay | 2 | 插值渲染延迟（tick） |
| JoinTimeout | 100 | 握手/基线超时（步） |
| CorrectionRate | 0.25 | 预测修正平滑系数 [0,1] |
| FadeTicks | 4 | 进出视野淡入淡出（tick） |

## 测试覆盖

- `world`：确定性移动、输入钳制、增删实体、历史基线、增量与全量一致性、视野筛选。
- `transport`：丢包、重复、乱序、带宽尾丢、按目的地投递、在途上限、编解码往返。
- `server`：重复/过期输入无效果、未知会话输入忽略、确定性顺序、基线重传、增量只含变化、增量重建全量。
- `client`：加入流程、基线前不渲染、基线丢失重试、预测收敛、预测不破坏插值、进出视野淡入淡出、过期快照丢弃。
- 集成：多客户端混沌收敛（丢包+乱序+重复）、实体增删一致性、拥塞退让、预测修正无跳变、中途加入、重复乱序快照。
